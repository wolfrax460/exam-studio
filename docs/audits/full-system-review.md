# Exam Studio full system review

## Scope and architecture

This review compares the first runnable 0.2.1 tree with GitHub main at the Task 024 merge. The [inventory](legacy-system-inventory.md) maps 18 areas and all 159 current method/path registrations across five Express files. The baseline contained 35 registered routes and 80 tracked files. The comparison tree contained 332 tracked files and 25 model files. Those file totals describe the trees and include assets, tests and tooling. Review concentrated on application entry points, routes, persistence, renderers and tests.

The baseline combined a React/Vite frontend, one Express entry point, a shared exam-format library, provider and renderer modules, a Mongo/JSON repository, a local MCP server and an Electron wrapper. The current app still uses that structure. The largest additions are the separate marketing build, remote MCP and API tokens, hosted online exams, platform admin, rich notes and institutions. Task 024 has already landed. Its Courses and Lessons, written grading and Paper Studio changes were checked against their consumers and regression suites. This audit did not reimplement those services.

## API behavior and architecture

- **Entry and middleware.** [index.js](../../server/index.js) uses Helmet, configured CORS, a 4 MB JSON limit, route-specific rate limiting and a final JSON error handler. Auth gates depend on registration order. Public account, health, public API metadata, MCP and take routes are deliberately exposed ahead of or excluded from the JWT gate. The general API gate, institution router and admin guard have different scopes. Async route wrappers normalize expected errors. Mongoose cast/validation errors, duplicate records and Multer limits get separate responses. Payload validation is per handler, so depth varies by operation.
- **Auth and API tokens.** [auth.js](../../server/lib/auth.js) reloads the current account for authenticated requests. JWT expiry/version, account state, role and institution membership are distinct checks. Versioned REST uses the same JWT revocation rule. REST and authenticated MCP check current PAT account state and the required generation or Library scope. MCP session close is bound to the account that opened it. Legacy `read` still grants Library reads. Server/reverse-proxy logs should redact credential-bearing MCP compatibility paths. Logout clears the browser JWT, while privileged signout and reset can increment the server-side token version.
- **Business routes.** Personal Library reads/deletes combine an item ID with the authenticated owner. Institution mutations derive the workspace from resolved membership and apply role and record-scope policy. Online exam owner routes recheck Library ownership. Public take responses use a separate student projection. Validation covers common text lengths, enum/state checks, revision checks, exam deadlines and answer shape. Legacy export handlers validate the outer paper shape and some nested render data still relies on format-specific assumptions.
- **Ordering and inactive code.** The literal route inventory has no duplicate method/path pair. The parameterized MCP GET handler precedes the explicit public GET handler and matches the public path first. Both send method guidance. The standalone OAuth models are present, but the Express OAuth prefix returns 404 for unknown routes and current MCP authentication uses PATs. Audit consumers before removing compatibility code.
- **External work.** Generation calls configured provider APIs or the compatible CLI. Notes/handouts/exams/cards build structured prompts from user content, use tool schemas or structured parsing and validate output in format-specific code. Mail uses optional SMTP. Google Sheets uses a server-configured service account and a share link. Update checks use a release feed. They were reviewed without sending real mail, provider requests or Google Sheets exports.
- **Coupling.** The Express entry owns authentication, API/MCP transports, exam lifecycle, polling, exports and admin routes. Institution routers show an existing extraction pattern. Split public take and owner exam handlers behind unchanged contracts as a later step. Preserve route-order tests while extracting. Avoid unifying storage behavior where the backends support different capabilities.

## Persistence, performance and safety

| Area | Finding |
| --- | --- |
| MongoDB | User email is indexed uniquely. Library queries scope by owner and ownership mode. Institution membership and course state are versioned or uniquely scoped through their models. Online attempts use Mongo models, version checks and deadline/state queries. Lists and aggregations should be measured against representative synthetic volumes before changing indexes. |
| JSON store | Designed for one process with in-memory state and synchronous atomic file replacement. It handles older arrays and retains a corrupt-file copy where possible. It does not offer Mongo transaction, indexing or concurrency semantics. Startup fallback after an unreachable configured database can present a different store. Keep production fail-closed policy and any data migration separate from desktop compatibility. |
| Browser data | Per-user Study Guide last-output pointers already isolate that cache. The three module-builder keys predate account ownership and are visible across accounts sharing one browser profile. The audit did not claim historical records on behalf of a signed-in account. A verified export/restore and account-scoped storage design is required before changing those keys. |
| Large reads | Personal Library and attempt lists are unpaginated. Exam stats currently load the full matching attempt set before aggregating. Admin has capped page sizes on its main high-volume views. Introduce pagination with backward-compatible client and API consumers rather than silently limiting existing arrays. |
| Uploaded and generated files | Multipart files are held in memory. OCR work can be CPU-heavy and has a page cap. Built documents are streamed as attachments from memory. The file-download route is rooted at the dedicated downloads folder. Electron verifies the selected installer digest and leaves installation to the user. |
| Generation accounting | Daily Mongo usage checks and increments are separate operations. A burst can race the read, and the file backend does not use the same daily counter. Plan limits and MCP quotas are separate. Establish one documented accounting contract and atomic reservations with refunds before relying on a hard budget across processes. |
| Secret handling | Production startup requires a configured non-placeholder JWT secret. Provider secrets are encrypted when an appropriate master key is configured and settings responses return metadata rather than raw API keys. The test runs used loopback data, demo output and synthetic credentials. The production server dependency audit reported zero advisories at audit time. |

The client and landing audits each reported a high Vite finding and a moderate esbuild finding in development tooling. Production serves built assets through Express and Vercel. A dedicated upgrade should verify the Vite plugin, Tailwind, metadata generation and browser suite in both projects. See the [Vite advisory](https://github.com/vitejs/vite/security/advisories/GHSA-4w7w-66w2-5vf9).

## Subjective marking and result release

Task 024's `aiMarkAnswer` uses the rubric, student text and optional part allocations. Its prompt accepts paraphrases and alternative reasoning and asks for half-point increments. Validation rejects malformed, out-of-range, uncertain and inconsistent provider results. The exam owner's provider is selected, and uncertainty keeps the question pending. Teacher review can override a mark with a revision check. Regrade excludes teacher-reviewed marks. Student results honor publication visibility and avoid sending the marking scheme or internal reviewer metadata. The server suites exercise those properties with fixture responses. The browser flow exercises a synthetic objective mark followed by teacher review of a written answer. No live model accuracy or production grade changes were part of this audit.
